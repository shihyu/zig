彙編 ​

儘管現代高級語言的特性已經非常豐富，但我們仍需要彙編語言的幫助，在某些特殊的場景下，彙編語言可以發揮出比高級語言更好的性能，這是因為彙編語言更加接近硬件，它允許我們對硬件直接進行操作。

一般是在以下場景下，才會涉及到使用匯編語言：

  1. 時效性高的程序，例如工業控制的程序。
  2. 驅動程序，這需要直接操控硬件，由於高級語言的抽象層次過高，導致其不如彙編語言來的方便。
  3. 內核的開發，現代化內核編寫時均會使用匯編來完成一些初始化工作，如 bootloader，分段分頁，中斷處理等。
  4. 程序的優化，高級語言的編譯器並不是完美的，它有時會做出反而使程序變慢的“優化”，而彙編語言完全由程序員控制。

在 Zig 中使用匯編有兩種主要方式：外部彙編和內聯彙編。內聯彙編是更常用的方式。

🅿️ 提示

對於 x86 和 x86_64，當前彙編語法為 AT＆T 語法，而不是更流行的 Intel 語法。這是由於技術限制，彙編解析由 LLVM 提供，其對 Intel 語法的支持存在 bug 且測試​​結果並不理想。

在未來的某一天 Zig 可能有自己的彙編器。這將使彙編能夠更加無縫地集成到語言中，並與流行的 Nasm 語法兼容。

外部彙編 ​

兩種方式引入外部彙編，一種是在 build.zig 中使用 addAssemblyFile 添加彙編文件，另一種是通過 zig 本身的全局彙編功能。

這裡講述全局彙編功能：當彙編表達式出現在容器級 comptime 塊中時，就是全局彙編。

🅿️ 提示

你可能對於容器這個概念比較疑惑，在 Zig 中，容器是充當保存變量和函數聲明的命名空間的任何語法結構。容器也是可以實例化的類型定義。結構體、枚舉、聯合、不透明，甚至 Zig 源文件本身都是容器，但容器並不能包含語句（語句是描述程序運行操作的一個單位）。

當然，你也可以這樣理解：容器是一個只包含變量或常量定義以及函數定義的命名空間。

注意：容器和塊（block）不同！

它的實際作用就和使用 addAssemblyFile 的效果類似，在編譯期它們會被提取出來作為單獨的彙編文件進行編譯和鏈接。

zig
const std = @import("std");

comptime {
    asm (
        \\.global my_func;
        \\.type my_func, @function;
        \\my_func:
        \\  lea (%rdi,%rsi,1),%eax
        \\  retq
    );
}

extern fn my_func(a: i32, b: i32) i32;

pub fn main() void {
    std.debug.print("{}\n", .{my_func(2, 5)});
}

以上這段函數中，我們通過全局彙編定義了一個彙編函數，以實現加法功能，並在 main 中實現了調用，如果你想了解更多這些相關的內容，你可以繼續查詢有關調用約定（Calling convention）的資料。

內聯彙編 ​

內聯彙編允許我們將底層彙編代碼與高級語言相結合，以實現更高效或更直接的操作。

zig
const std = @import("std");

pub fn main() noreturn {
    // Temporarily disabled due to Zig 0.15 syntax changes
    // const msg = "hello world\n";
    // _ = syscall3(SYS_write, STDOUT_FILENO, @intFromPtr(msg), msg.len);
    // _ = syscall1(SYS_exit, 0);
    std.process.exit(0);
}

pub const SYS_write = 1;
pub const SYS_exit = 60;

pub const STDOUT_FILENO = 1;

// Temporarily disabled due to Zig 0.15 inline assembly syntax changes
// TODO: Update to new Zig 0.15 inline assembly syntax

// pub fn syscall1(number: usize, arg1: usize) usize {
//     var result: usize = undefined;
//     asm volatile ("syscall"
//         : [ret] "={rax}" (result)
//         : [number] "{rax}" (number),
//           [arg1] "{rdi}" (arg1)
//         : "rcx", "r11"
//     );
//     return result;
// }

// pub fn syscall3(number: usize, arg1: usize, arg2: usize, arg3: usize) usize {
//     var result: usize = undefined;
//     asm volatile ("syscall"
//         : [ret] "={rax}" (result)
//         : [number] "{rax}" (number),
//           [arg1] "{rdi}" (arg1),
//           [arg2] "{rsi}" (arg2),
//           [arg3] "{rdx}" (arg3)
//         : "rcx", "r11"
//     );
//     return result;
// }

上面這段代碼是通過內聯彙編實現在 x86-64 linux 下輸出 hello world，接下來講解一下它們的組成和使用。

內聯彙編是以 asm 關鍵字開頭的一個表達式，這說明它可以返回值（也可以不返回值），volatile 關鍵字會通知編譯器，內聯彙編的表達式會被某些編譯器未知的因素更改（例如操作系統，硬件 MMIO 或者其他線程等等），這樣編譯器就不會額外優化這段內聯彙編。

上面就是基本的內聯彙編的一個外部結構說明，接下來我們介紹具體的內部結構：

zig
asm volatile ("assembly code"
        : [ret] "={rax}" (-> usize),
        : [number] "{rax}" (number),
          [arg1] "{rdi}" (arg1),
          [arg2] "{rsi}" (arg2),
          [arg3] "{rdx}" (arg3),
        : "rcx", "r11"
    );

結構大體是這樣的：

asm
# 別忘記三個冒號，即便對應的部分不存在也需要有冒號
AssemblerTemplate
: OutputOperands
[ : InputOperands
[ : Clobbers ] ]
  1. 首先是一個內聯彙編的語句，但它和普通的內聯語句不同，它可以使用“佔位符”，類似%[value]，這就是一個佔位符，以 % 開頭，如果需要使用寄存器，則需要使用兩個 % ，例如使用 CR3 寄存器就是 %%cr3。
  2. 之後是一個輸出位置，它表示你需要將值輸出到哪裡，也可以沒有返回值，例如上方的示例中 [ret] "={rax}" (-> usize) 代表我們使用 [ret] 標記了返回值，並且返回值就是 rax 寄存器中的值，其後的 (-> usize) 代表我們整個內聯彙編表達式需要返回一個值，當然這裡如果是一個變量，就會將 rax 寄存器的值通過[ret]標記綁定到變量上。（注意，此處的 = 代表只能進行寫入操作數，屬於是一個約束。）
  3. 這是輸入操作數，它和輸出位置類似，但它可以存在多個輸入，並且它也支持“佔位符”和相關的約束。
  4. 這裡是改動的寄存器，用於通知編譯器，我們在執行此內聯彙編會使用（或者稱之為破壞更合適）的寄存器，默認包含了輸入和輸出寄存器。還有一個特殊標記 memory，它會通知編譯器內聯彙編會寫入任意為聲明的內存位置。

🅿️ 提示

關於更多的內聯彙編約束信息，你可以閱讀這裡：LLVM documentation，GCC documentation。

WARNING

內聯彙編特性在未來可能會發生更改以支持新的特性（如多個返回值），具體見此 issue。
