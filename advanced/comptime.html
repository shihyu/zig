編譯期 ​

在開始之前，我們需要先梳理一下，什麼是編譯期？

對於這個概念，你可能會一臉懵逼。所以我們先看一下什麼是運行時（runtime）：

“在計算機科學中代表一個計算機程序從開始執行到終止執行的運作、執行的時期。”

對應地，我們可以嘗試給編譯期做一個定義：“zig 編譯期是指在 zig 編譯期間執行的動作。”

🅿️ 提示

在 Zig 中，類型是一等公民。它們可以分配給變量，作為參數傳遞給函數，並從函數返回。但需要注意：它們只能用於編譯期已知的語句或函數中！

通常一個編譯期已知的語句或函數帶有 comptime 關鍵字！

comptime 這個關鍵字表示：

  • 在這個調用點，標記的值必須是在編譯期已知的，否則 zig 會報告錯誤！
  • 在函數定義中，該值（包括參數、類型）必須是編譯期已知的（但無需全部都是編譯期已知的，僅保證依賴關係中的符合即可）！

編譯期參數實現鴨子類型 ​

“當看到一隻鳥走起來像鴨子、游泳起來像鴨子、叫起來也像鴨子，那麼這隻鳥就可以被稱為鴨子。”

一個實現 max 功能的函數：

zig
fn max(comptime T: type, a: T, b: T) T {
    return if (a > b) a else b;
}

以上，我們定義了一個函數，它包含一個編譯期參數 T，這個 T 的類型是 type，也就是一個類型，同時其他的參數和返回值類型也都是 T，這意味著參數類型與返回值類型是一致的。

很明顯，上述的 max 函數僅僅只能比較整數和浮點數，我們可以稍稍改造它一下變成 maxPlus，使之支持布爾值：

zig
fn maxPlus(comptime T: type, a: T, b: T) T {
    if (T == bool) {
        return a or b;
    } else if (a > b) {
        return a;
    } else {
        return b;
    }
}

我們可以看到，T 是一個參數（參數在 zig 中均是隻讀的），我們可以正常把它當作常量來使用。

🅿️ 提示

上面操作可行的原因：

因為編譯期會在編譯期隱式內聯 if 表達式，並且會跳過對未使用的分支的分析（可以簡單看作刪掉了該分支），所以當傳入的 T 是 bool 時，編譯後的結果是這個樣子：

zig
fn max_actual(a: bool, b: bool) bool {
    {
        return a or b;
    }
}

這些額外未使用的分支在編譯時會被“裁剪掉”，只保留運行時所需要的分支。

TIP

注意：這也適用於 switch。

編譯期變量 ​

變量可以也標記上 comptime，標記變量是編譯期已知的。這會通知編譯器，該變量的讀取和寫入完全是在編譯期執行的，任何發生運行時對變量的操作將會在編譯時報錯。

該特性可以與 inline 一起使用，以下的示例僅僅是示範作用（實際沒有必要這麼操作）：

zig
fn performFn(comptime prefix_char: u8, start_value: i32) i32 {
    var result: i32 = start_value;
    // 以下的变量 i 被标记为编译期已知的
    comptime var i = 0;
    // 这里将会被内联，实际编译出来的代码将不包含循环
    // 原因是cmd_fns是一个常量，那么代表它是编译期可知的
    // 也就是说整个循环的执行结果在编译期就可以确定
    inline while (i < cmd_fns.len) : (i += 1) {
        if (cmd_fns[i].name[0] == prefix_char) {
            result = cmd_fns[i].func(result);
        }
    }
    return result;
}
zig
const expect = @import("std").testing.expect;

const CmdFn = struct {
    name: []const u8,
    func: fn (i32) i32,
};

// 这里的 cmd_fns 是一个常量，所以它是编译期可知的
const cmd_fns = [_]CmdFn{
    CmdFn{ .name = "one", .func = one },
    CmdFn{ .name = "two", .func = two },
    CmdFn{ .name = "three", .func = three },
};

fn one(value: i32) i32 {
    return value + 1;
}
fn two(value: i32) i32 {
    return value + 2;
}
fn three(value: i32) i32 {
    return value + 3;
}

fn performFn(comptime prefix_char: u8, start_value: i32) i32 {
    var result: i32 = start_value;
    // 以下的变量 i 被标记为编译期已知的
    comptime var i = 0;
    // 这里将会被内联，实际编译出来的代码将不包含循环
    // 原因是cmd_fns是一个常量，那么代表它是编译期可知的
    // 也就是说整个循环的执行结果在编译期就可以确定
    inline while (i < cmd_fns.len) : (i += 1) {
        if (cmd_fns[i].name[0] == prefix_char) {
            result = cmd_fns[i].func(result);
        }
    }
    return result;
}

pub fn main() !void {
    try expect(performFn('t', 1) == 6);
    try expect(performFn('o', 0) == 1);
    try expect(performFn('w', 99) == 99);
}

針對不同的參數，實際上會在編譯期生成不同的代碼：

TIP

注意：以下函數命名僅僅是為了區分才如此命名！

zig
fn performFn_for_t(start_value: i32) i32 {
    var result: i32 = start_value;
    result = two(result);
    result = three(result);
    return result;
}
zig
fn performFn_for_o(start_value: i32) i32 {
    var result: i32 = start_value;
    result = one(result);
    return result;
}
zig
fn performFn_for_w(start_value: i32) i32 {
    var result: i32 = start_value;
    _ = &result;
    return result;
}

🅿️ 提示

這種編譯期變量的實現，更多是為了代替需要使用宏、代碼生成、預處理器的場景。

編譯期表達式 ​

通過 comptime 標記告訴編譯器表達式需要在編譯期完成計算，如果無法完成計算，編譯器將會報告錯誤。

對於一個編譯期表達式，它有以下特性：

  • 所有變量都是 comptime 變量
  • 所有 if、while、for 和 switch 表達式都在編譯時求值，否則報告編譯錯誤。
  • 所有 return 和 try 表達式都是無效的（除非函數本身在編譯時被調用）。
  • 所有具有運行時副作用或依賴於運行時值的代碼都會觸發編譯錯誤。
  • 所有函數調用都會導致編譯器在編譯時分析該函數，如果該函數嘗試執行具有全局運行時副作用的操作，則會觸發編譯錯誤。

🅿️ 提示

故我們無需專門為編譯期表達式編寫函數，只需要編寫普通的函數就行。

一個簡單的斐波那契數列函數：

zig
fn fibonacci(index: u32) u32 {
    if (index < 2) return index;
    return fibonacci(index - 1) + fibonacci(index - 2);
}

pub fn main() !void {
    const expect = @import("std").testing.expect;

    // 运行时测试
    try expect(fibonacci(7) == 13);

    // 编译期测试
    try comptime expect(fibonacci(7) == 13);
}

以上函數實現了 斐波那契數列，注意到我們使用的是遞歸方法來實現，在編譯期，堆棧的嵌套層數最大是：1000，如果超過了這個值，可以使用 @setEvalBranchQuota，來修改默認的堆棧嵌套。

🅿️ 提示

注意：當前的自託管編譯期設計存在某些缺陷（使用自己的堆棧進行 comptime 函數調用），當宿主機器並沒有提供足夠大的堆棧時，將導致堆棧溢出，具體問題可以見這個 issue。

在容器（Container）級別（任何函數之外），所有表達式都是隱式的 comptime 表達式，這意味著我們可以使用函數來初始化複雜的靜態數據。例如：

zig
const c = add_comptime(1, 2);

fn add_comptime(comptime a: usize, comptime b: usize) usize {
    return a + b;
}

add_comptime 函數作為編譯期可執行函數，我們用它來進行數據的初始化，當然我們這裡可以直接賦值為 3，這裡僅僅作為示例。當我們在處理複雜數據時很有用。

生成數據結構 ​

通過使用編譯期特性，可以使用 comptime 來生成數據結構，無需引入額外語法。

zig
fn List(comptime T: type) type {
    return struct {
        items: []T,
        len: usize,
    };
}

var buffer: [10]i32 = undefined;

var list = List(i32){
    .items = &buffer,
    .len = 0,
};

以上代碼，我們通過 List 函數初始化變量 list，它是一個結構體的示例，List(i32) 返回的是一個結構體類型。

🅿️ 提示

關於這個結構體的名字，它是由編譯器決定的，根據創建匿名結構體時調用的函數名稱和參數推斷出名稱為List(i32)。

例如簡單實現一個單鏈表的結構：

zig
const Node = struct {
    next: ?*Node,
    name: []const u8,
};

var node_a = Node{
    .next = null,
    .name = "Node A",
};

var node_b = Node{
    .next = &node_a,
    .name = "Node B",
};

在此示例中，Node 結構引用自身。這完全可行，因為所有頂級聲明都是與順序無關的。

只要編譯器可以確定結構的大小，就可以自由地引用其自身。

在這種情況下，Node 將自身稱為指針，該指針在編譯時具有明確定義的大小，因此它可以正常工作。
