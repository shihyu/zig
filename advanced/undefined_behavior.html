未定義操作 ​

zig 本身有許多未定義行為，它們可以很方便地幫助開發者找出錯誤。

如果在編譯期就檢測到了未定義的行為，那麼 zig 會發出編譯錯誤並停止繼續編譯，大多數編譯時無法檢測到的未定義行為均會在運行時被檢測到。這就是 zig 的安全檢查！

WARNING

注意：本章節並沒有 CI 檢查，故可能存在內容過期的情況，具體可參考 官方手冊。

安全檢查會在 debug、ReleaseSafe 模式下開啟，但可以使用 @setRuntimeSafety 來強制指定在單獨的塊中是否開啟安全檢查（這將忽略構建模式）。

當出現安全檢查失敗時，zig 會編譯失敗並觸發堆棧跟蹤：

test "safety check" {

}

以下說明各種未定義行為。

不可達代碼 ​

即 unreachable，如果程序執行到它，那麼會觸發完整的堆棧跟蹤！

索引越界訪問 ​

無論是數組還是切片，發生越界訪問會發生錯誤導致程序終止進而觸發堆棧跟蹤！

負數轉換為無符號整數 ​

這本身就是非法行為，故會直接出現報錯，如果僅僅是想要將負數當作無符號整數看待，可以使用 @bitCast。

如果想要獲取到無符號整數的最大值，可以使用 std.math.maxInt。

數據截斷 ​

注意我們這裡指的是數據類型的範圍變小了，不足以容納數據的值，例如：

zig
const spartan_count: u16 = 300;
const byte: u8 = @intCast(spartan_count);

上面這段代碼毫無疑問會失敗，因為 u8 類型無法容納下 300 這個數。

除非，我們顯式強制截斷位，使用 @truncate。

整數溢出 ​

常規的運算可能導致溢出，如加 + 減 - 乘 * 除 / 取反 - 運算可能出現溢出。

還有 @divTrunc、@divFloor、@divExact，可能造成溢出。

標準庫提供的函數可能存在溢出：

  • @import("std").math.add
  • @import("std").math.sub
  • @import("std").math.mul
  • @import("std").math.divTrunc
  • @import("std").math.divFloor
  • @import("std").math.divExact
  • @import("std").math.shl

為了處理這些情況，zig 提供了幾個溢出檢測函數來處理溢出問題：

  • @addWithOverflow
  • @subWithOverflow
  • @mulWithOverflow
  • @shlWithOverflow

以上這些內建函數會返回一個元組，包含計算的結果和是否發生溢出的判斷位。

zig
const print = @import("std").debug.print;
pub fn main() void {
    const byte: u8 = 255;

    const ov = @addWithOverflow(byte, 10);
    if (ov[1] != 0) {
        print("overflowed result: {}\n", .{ov[0]});
    } else {
        print("result: {}\n", .{ov[0]});
    }
}

除此以外，我們還可以使用環繞（Wrapping）操作來處理計算：

  • +% 加法環繞
  • -% 減法環繞
  • -% 取否環繞
  • *% 乘法環繞

它們會取計算後溢出的值！

移位溢出 ​

進行左移操作時，可能導致結果溢出，此時程序或者編譯器會停止併發出警告！

除零操作 ​

很顯然，除零是非法操作，故會引起程序或者編譯器報錯！

當然，還包括求餘運算，除數為零是也是非法的！

精確除法溢出 ​

精確除法使用的是 @divExact，它需要保證被除數可以整除除數，否則會觸發編譯器錯誤！

嘗試解開可選類型 Null ​

可選類型值是 null 時，如果直接使用 variable.? 語法來解開可選，那麼會導致出現錯誤！

正確的處理方案是使用 if 語法來解開可選類型。

嘗試解開錯誤聯合類型 Error ​

錯誤聯合類型如果是 error 時，直接使用它會導致程序或者編譯器停止運行！

正確的處理方案是使用 if 語法來解開可選類型。

無效錯誤碼 ​

使用 @errorFromInt 獲取錯誤時，如果沒有對應整數的錯誤，那麼會導致程序或編譯器報錯！

無效枚舉轉換 ​

當使用 @enumFromInt 來獲取枚舉時，如果沒有對應整數的枚舉，那麼會導致程序或者編譯器報告錯誤！

無效錯誤集合轉換 ​

兩個不相關的錯誤集不可以相互轉換，如果強制使用 @errorCast轉換兩個不相關的錯誤集，那麼會導致程序或者編譯器報告錯誤！

指針對齊錯誤 ​

指針對齊轉換可能發生錯誤，如：

zig
const ptr: *align(1) i32 = @ptrFromInt(0x1);
const aligned: *align(4) i32 = @alignCast(ptr);

0x1 地址很明顯是不符合 4 字節對齊，會導致編譯器錯誤。

聯合類型字段訪問錯誤 ​

如果訪問的聯合類型字段並非是它當前的有效字段，那麼會觸發非法行為！

可以通過重新分配來更改聯合類型的有效字段：

zig
const Foo = union {
    float: f32,
    int: u32,
};

var f = Foo{ .int = 42 };
f = Foo{ .float = 12.34 };

🅿️ 提示

注意：packed 和 extern 標記的聯合類型並沒有這種安全監測！

浮點轉換整數發生越界 ​

當將浮點數轉換為整數時，如果浮點數的值超出了整數類型的範圍，就會發生非法越界，例如：

zig
const float: f32 = 4294967296;
const int: i32 = @intFromFloat(float);

指針強制轉換為 Null ​

將允許地址為 0 的指針轉換為地址不可能為 0 的指針，這會觸發非法行為。

C 指針、可選指針、allowzero 標記的指針，這些都是允許地址為 0，但普通指針是不允許的。
