函數 ​

函數是編程語言中最為基本的語句。

基本使用 ​

Zig 的函數結構清晰，你可以一眼看出其組成部分。我們來用一個簡單的函數作為說明：

zig
pub fn add(a: u8, b: u8) u8 {
    return a + b;
}

如果你有 C 的使用經驗，一眼就可以看出來各自的作用。

具體說明如下：

  1. pub 是訪問修飾符，表示函數是公共可訪問的（其他文件 import 該文件後可以直接使用此函數）。
  2. fn 是關鍵字，用於定義函數。
  3. add 是標識符，作為函數名。
  4. a: u8 是參數的標識符和類型。這裡有兩個參數 a 和 b，它們的類型都是 u8。
  5. u8 是函數的返回類型。在 Zig 中，一個函數只能返回一個值。

如果沒有返回值，請使用 void。Zig 原則上不允許忽略函數的返回值；如果需要忽略，可將返回值分配給 _，編譯器將自動忽略該返回值。

🅿️ 提示

你可能注意到了有的函數定義是這樣子的：

zig
fn max(comptime T: type, a: T, b: T) T {
    return if (a > b) a else b;
}

其中 comptime T: type 可能對你來說比較陌生，這是編譯期參數，它是實現鴨子類型（泛型）的關鍵語法。

關於函數命名

這裡命名規則沒什麼強制性的要求，你只需要保證符合變量聲明的 標識符規範 即可。

如果你需要命名規範的建議，可以參考 Zig 源碼的命名方式，它使用的是小駝峰命名法。

WARNING

函數體和函數指針之間存在區別：函數體是僅限編譯時的類型，而函數指針可能是運行時已知的。

例如，*const fn (a: i8, b: i8) i8 就是一個函數指針類型。

參數傳遞 ​

參數傳遞是一個經典問題。在高級語言中，存在“值傳遞”和“引用傳遞”兩種情況，這無疑增加了程序員的認知負擔。

Zig 在這方面的處理是：原始類型（如整型、布爾）完全使用值傳遞。對於原始類型，這種策略開銷非常小，通常只需設置對應的寄存器即可。

對於複合類型（如結構體、聯合、數組），編譯器會根據具體情況決定是使用“值傳遞”還是“引用傳遞”。

但作為開發者，你只需要記住：函數的參數是不可變的。

🅿️ 提示

對於外部函數（使用 extern 修飾），Zig 遵循 C ABI（應用程序二進制接口）按值傳遞結構體和聯合類型。

內建函數 ​

內建函數由編譯器提供，並以 @ 為前綴。參數上的 comptime 關鍵字意味著該參數必須在編譯期已知。

由於內建函數數量眾多，本教程不進行系統講解，僅在相關章節說明涉及到的內建函數。

更多內建函數的文檔請參考這裡。

高階使用 ​

以下是一些更加高級的用法，可以之後再學習！

閉包 ​

首先，我們來看維基百科對閉包的定義：

在計算機科學中，閉包（英語：Closure），又稱詞法閉包（Lexical Closure）或函數閉包（function closures），是在支持頭等函數的編程語言中實現詞法綁定的一種技術。

閉包在實現上是一個結構體，它存儲了一個函數（通常是其入口地址）和一個關聯的環境（相當於一個符號查找表）。

環境裡是若干對符號和值的對應關係，它既要包括約束變量（該函數內部綁定的符號），也要包括自由變量（在函數外部定義但在函數內被引用），有些函數也可能沒有自由變量。閉包跟函數最大的不同在於，當捕捉閉包的時候，它的自由變量會在捕捉時被確定，這樣即便脫離了捕捉時的上下文，它也能照常運行。

捕捉時對於值的處理可以是值拷貝，也可以是名稱引用，這通常由語言設計者決定，也可能由用戶自行指定（如 C++）。

在 Zig 中，由於語言設計上的某些限制，我們無法像在某些其他語言中那樣自由地使用閉包特性。

廣義上講，閉包是指一個函數與其引用的詞法作用域（lexical scope）形成的組合。簡言之，閉包允許一個函數訪問其外部作用域中的變量，即使這個函數在其外部作用域之外被調用。其主要特性是能夠“記住”其創建時的環境。

在許多支持內存垃圾回收（GC）的語言中，它們的使用大概是這樣的：

python
def outer_function():
    message = "Hello, World!"  # 外部函數的局部變量

    def inner_function():
        print(message)  # 內部函數訪問外部函數的變量

    return inner_function  # 返回內部函數

# 創建閉包
closure = outer_function()

# 調用閉包
closure()  # 輸出：Hello, World!

以上是一段 Python 代碼。其中 outer_function 函數最終返回一個函數類型（實際上它返回了 inner_function 函數，但在解釋執行時，它不再以 inner_function 的名稱存在）。

Zig 語言不允許在函數內部聲明函數，也不允許直接創建匿名函數。這兩個特性在其他編程語言（例如 JavaScript、PowerQuery-M 等）中是實現閉包模式的常見方式。

因此，在 Zig 中實現閉包，通常需要其在編譯期是已知的：

zig
fn bar(comptime x: i32) fn (i32) i32 {
    return struct {
        pub fn foo(y: i32) i32 {
            var counter = 0;
            for (x..y) |i| {
                if ((i % 2) == 0) {
                    counter += i * i;
                }
            }
            return counter;
        }
    }.foo;
}

函數 bar 返回一個 fn (i32) i32 類型的函數，並接收一個編譯期參數。這使得該函數可以訪問編譯期傳入的數據。需要注意的是，這裡我們使用了匿名結構體方法。

關於閉包的更多內容可以參考以下文章或帖子：

  • Implementing Closures and Monads in Zig
  • Closure Pattern in Zig Zig

關於 Andrew Kelley 拒絕匿名函數提案的解釋：

  • RFC: Make function definitions expressions

anytype ​

函數參數可以用 anytype 代替類型來聲明。在這種情況下，調用函數時將推斷參數類型。使用 @TypeOf 和 @typeInfo 獲取有關推斷類型的信息。

zig
fn addFortyTwo(x: anytype) @TypeOf(x) {
    return x + 42;
}

noreturn ​

noreturn 是一個特殊類型，表示函數不會返回。它通常用於以下情況：

  • break
  • continue
  • return
  • unreachable
  • while (true) {}

當一個函數不會返回時，可以使用它來代替 void。

該類型常用於內核開發，因為內核本身通常是一個不會退出的程序。另一個使用場景是 exit 函數。

zig
const WINAPI = @import("std").os.windows.WINAPI;
extern "kernel32" fn ExitProcess(exit_code: c_uint) callconv(WINAPI) noreturn;

export ​

export 關鍵字確保函數在生成的目標文件 (object file) 中可見，並遵循 C ABI。

zig
export fn sub(a: i8, b: i8) i8 {
    return a - b;
}

extern ​

extern 說明符用於聲明一個將在鏈接時解析的函數（即該函數並非由 Zig 定義，而是由外部庫定義，通常遵循 C ABI，但 C ABI 本身有多種規範）。鏈接可以是靜態鏈接或動態鏈接。extern 關鍵字後面引號中的標識符指定了包含該函數的庫（例如 c -> libc.so）。callconv 說明符用於更改函數的調用約定。

zig
extern "c" fn atan2(a: f64, b: f64) f64;

TIP

extern 用於引用非 Zig 實現的庫，而 export 則是 Zig 將函數對外暴露供其他語言使用！

@setCold ​

@setCold(comptime is_cold: bool) void

告訴優化器當前函數很少被調用（或不被調用）。該函數僅在函數作用域內有效。

zig
fn abort() noreturn {
    @branchHint(.cold);
    while (true) {}
}

callconv ​

callconv 關鍵字用於指定函數的調用約定，這在對外暴露函數或編寫裸彙編時非常有用。

zig
// 强制该函数在所有被调用位置内联，否则失败。
inline fn shiftLeftOne(a: u32) u32 {
    return a << 1;
}

關於可用的調用約定格式，請參考std.builtin.CallingConvention。
