數值類型 ​

數值類型是編程語言中最基本的數據類型之一。當它們被編譯成機器碼時，通常會對應到 CPU 運算器的操作指令。

整數 ​

類型 ​

在 Zig 中，整數類型劃分非常詳細，具體如下表所示：

類型對應 C 類型描述
i8int8_t有符號 8 位整數
u8uint8_t無符號 8 位整數
i16int16_t有符號 16 位整數
u16uint16_t無符號 16 位整數
i32int32_t有符號 32 位整數
u32uint32_t無符號 32 位整數
i64int64_t有符號 64 位整數
u64uint64_t無符號 64 位整數
i128__int128有符號 128 位整數
u128unsigned __int128無符號 128 位整數
isizeintptr_t有符號指針大小的整數
usizeuintptr_t size_t無符號指針大小的整數
comptime_int無編譯期的整數，整數字面量的類型
zig
// 下划线可以放在数字之间作为视觉分隔符
const one_billion = 1_000_000_000;
const binary_mask = 0b1_1111_1111;
const permissions = 0o7_5_5;
const big_address = 0xFF80_0000_0000_0000;

同時，Zig 支持任意位寬的整數。通過在 u（無符號）或 i（有符號）後加上數字即可定義，例如 i7 代表有符號的 7 位整數。整數類型允許的最大位寬為 65535。

🅿️ 提示

usize 和 isize 這兩種類型的大小取決於目標 CPU 架構：在 32 位系統上它們是 32 位，在 64 位系統上則是 64 位。

除零 ​

Zig 編譯器會在編譯期和運行時（ReleaseSmall 構建模式除外）對除零操作進行檢測。編譯時檢測到錯誤會直接停止編譯；運行時如果發生除零，則會給出完整的堆棧跟蹤。

小細節

這裡的“除零”包括了除法和求餘兩種操作。

編譯期：

zig
comptime {
    const a: i32 = 1;
    const b: i32 = 0;
    const c = a / b;
    _ = c;
}

溢出 ​

在 Zig 中，以下默認操作可能導致溢出：

  • +（加法）
  • -（減法）
  • -（取反）
  • *（乘法）
  • /（除法）
  • @divTrunc（除法）
  • @divFloor（除法）
  • @divExact（除法）

標準庫 @import("std").math 中的某些函數也可能導致溢出。

在編譯期和運行時，Zig 也會對溢出進行檢測，並提供類似“除零”操作的堆棧跟蹤。

處理溢出有兩種主要方式：使用內置的溢出處理函數，或使用環繞操作符。

內置溢出處理函數：

  • @addWithOverflow
  • @subWithOverflow
  • @mulWithOverflow
  • @shlWithOverflow

這些內建函數返回一個元組，其中包含一個布爾值（u1 類型）指示是否發生溢出，以及操作結果。

環繞操作符：

  • +%（加法環繞）
  • -%（減法環繞）
  • -%（取反環繞）
  • *%（乘法環繞）

這些操作符保證了環繞語義（即當結果超出類型範圍時，會從另一端“環繞”回來）。

浮點數 ​

浮點數用於表示帶有小數點的數字。在 Zig 中，浮點數類型包括 f16、f32、f64、f80、f128，以及 c_longdouble（對應 C ABI 的 long double）。

值得注意的是，comptime_float 具有 f128 的精度和運算能力。

浮點字面量可以隱式轉換為任意浮點類型。如果浮點字面量沒有小數部分，它還可以隱式轉換為任意整數類型。

浮點運算默認遵循 Strict 模式，但可以使用 @setFloatMode(.Optimized) 切換到 Optimized 模式。有關浮點運算模式的詳細信息，請參見 @setFloatMode。

🅿️ 提示

Zig 並未像其他語言那樣默認提供 NaN、無窮大、負無窮大等字面量語法。如果需要使用它們，請通過標準庫獲取：

zig
const std = @import("std");

const inf = std.math.inf(f32);
const negative_inf = -std.math.inf(f64);
const nan = std.math.nan(f128);
注意浮點數陷阱

  1. 由於計算機內部使用二進制表示，浮點數通常以近似值存儲（受限於浮點精度，例如某些分數無法精確表示）。

  2. 浮點數在某些操作上可能反直覺，這同樣是精度問題導致的。例如：

zig
const std = @import("std");

pub fn main() void {
    // assert 用於斷言，常用於單元測試和調試
    std.debug.assert(0.1 + 0.2 == 0.3);
}

你可能會認為這個斷言會通過，因為 0.1 + 0.2 顯然等於 0.3。但實際上，這段代碼在運行時會直接崩潰！

運算 ​

常規運算包括：等於 (==)，不等於 (!=)，大於 (>)，小於 (<)，大於等於 (>=)，小於等於 (<=)，加減乘除（+, -, *, /），左移右移 (<<, >>)，邏輯與或非 (and, or, !)，按位與 (&)，按位或 (|)，按位異或 (^)，按位非 (~)。

常見的加減乘除運算在此不再贅述，我們來聊聊 Zig 中獨具特色的一些操作符。

  • +|：飽和加法。這涉及到對等類型解析。簡單來說，加法結果不會超過該類型的最大值。例如，u8 類型的 255 加 1 後仍然是 255。
  • -|：飽和減法。與飽和加法類似，減法結果不會低於該類型的最小值。
  • *|：飽和乘法。乘法結果不會超過該類型的最大值或最小值。
  • <<|：飽和左移。左移結果不會超過該類型的最大值。
  • ++：數組串聯。要求兩個數組的元素類型相同。
  • **：數組重複。在編譯期已知數組的長度和重複次數。

🅿️ 提示

如果你需要使用複數，可以使用標準庫中的 std.math.Complex。

zig
const Complex = std.math.Complex(f64);
const i = Complex.init(0, 1);

// 虚数单位的平方
const z1 = i.mul(i);
print("i * i = ({d:.1},{d:.1})\n", .{ z1.re, z1.im });
// i * i = (-1.0,0.0)

// 使用常见函数
const z2 = std.math.complex.pow(i, Complex.init(2, 0));
print("pow(i, 2) = ({d:.1},{d:.1})\n", .{ z2.re, z2.im });
// pow(i, 2) = (-1.0,0.0)

// 欧拉公式
const z3 = std.math.complex.exp(i.mul(Complex.init(std.math.pi, 0)));
print("exp(i, pi) = ({d:.1},{d:.1})\n", .{ z3.re, z3.im });
// exp(i, pi) = (-1.0,0.0)

// 共轭复数
const z4 = Complex.init(1, 2).mul(Complex.init(1, -2));
print("(1 + 2i) * (1 - 2i) = ({d:.1},{d:.1})\n", .{ z4.re, z4.im });
// (1 + 2i) * (1 - 2i) = (5.0,0.0)
