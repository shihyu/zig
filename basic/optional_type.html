可選類型 ​

Overview ​

在 Zig 中，為了在不損害效率的前提下提高代碼安全性，可選類型是一個重要的解決方案。它的標誌是 ?，?T 表示該類型的值可以是 null 或 T 類型。

zig
// 一个普通的i32整数
const normal_int: i32 = 1234;

// i32的可选类型，现在它的值可以是 i32 或者 null
const optional_int: ?i32 = 5678;

通常，可選類型在指針上發揮作用，而非整數。

null（空引用）是許多運行時異常的根源，甚至被指責為計算機科學中最嚴重的錯誤。

我們可以通過可選類型來規避空引用問題。這是一種相對保守的做法，它同時兼顧了代碼的可讀性和運行效率。目前，Rust 在這方面更為激進，這增加了程序員在編寫代碼時的心智負擔（因為你需要經常與編譯期“鬥智鬥勇”，但好處是大大減少了運行時調試的負擔）。相對而言，Zig 採取了一種折中方案：在編譯期進行簡單的檢測，且檢測出的錯誤通常很容易糾正。然而，這種方案的缺點是不能保證運行時絕對安全（可選類型僅能避免空指針問題，但不能避免懸空指針、迷途指針和野指針等問題）。

Zig 對 null 有特殊處理，並保證 null 不會被賦值給一個非可選類型變量。

和 C 對比 ​

看看下面代碼中 Zig 和 C 在處理 null 上的區別。（嘗試調用 malloc 申請一塊內存。）

zig
// extern 用于连接标准 libc 的 malloc 函数，它是 posix 标准之一
extern fn malloc(size: usize) ?*u8;

fn doAThing() ?*Foo {
    // 尝试调用 malloc 申请内存，如果失败则返回null
    const ptr = malloc(1234) orelse return null;
    _ = ptr; // ...
}
c
// 引用的是 malloc 的原型
void *malloc(size_t size);

struct Foo *do_a_thing(void) {
    char *ptr = malloc(1234);
    if (!ptr) return NULL;
    // ...
}

在這裡，我們通過使用 orelse 解構了可選類型，確保 ptr 是一個合法可用的指針；如果 malloc 返回 null，則直接返回 null。（這看起來比 C 更加明瞭且易用。）

再看下例：

zig
fn doSomethingWithFoo(foo: *Foo) void {
    _ = foo;
}

fn doAThing(optional_foo: ?*Foo) void {
    // 干点什么。。。
    if (optional_foo) |foo| {
        doSomethingWithFoo(foo);
    }
    // 干点什么。。。
}
c
void do_a_thing(struct Foo *foo) {
    // 乾點什麼。。。
    if (foo) {
        do_something_with_foo(foo);
    }
    // 乾點什麼。。。
}

看起來區別不大，只是在 if 語法上有所不同。if 塊中保證 foo 不為 null。

當然，在 C 中，你可以使用 __attribute__((nonnull)) 來告訴 C 編譯器這裡不可能為 null，但其使用成本明顯比 Zig 高。

編譯期反射訪問可選類型 ​

WARNING

該部分內容需要編譯期反射的知識，可以選擇暫時跳過！

我們也可以通過編譯期函數來實現反射，進而訪問可選類型：

zig
// 声明一个可选类型，并赋值为 null
var foo: ?i32 = null;

// 重新赋值为子类型的值，这里是 i32
foo = 1234;

// 使用编译期反射来获取 foo 的类型信息
try comptime expect(@typeInfo(@TypeOf(foo)).optional.child == i32);

可選指針 ​

可選指針會保證與普通指針具有相同的大小，null 會被視為地址 0。
