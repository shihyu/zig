包管理 ​

隨著 0.11 的發佈，zig 終於迎來了一個正式的官方包管理器，此前需要通過第三方包管理器下載並處理包。

zig 當前並沒有一箇中心化存儲庫，包可以來自任何來源，無論是本地還是網絡上。

當前的包管理模式為，先在 build.zig.zon 添加包的元信息，然後在 build.zig 中引入包。

新的文件結構 ​

build.zig.zon 這個文件存儲了包的信息，它是 zig 新引入的一種簡單數據交換格式，使用了 zig 的匿名結構和數組初始化語法。

zig
.{
    // 包名字
    .name = .importer,
    // 包版本
    .version = "0.0.0",
    .fingerprint = 0x64e883e88dde22e2,
    // 包依赖
    .dependencies = .{
        // 包依赖项的名字
        .@"tarball-exporter" = .{
            .url = "https://github.com/zigcc/zig-msgpack/archive/33771261cc6bba98cee380392f6e95fbca30d956.tar.gz",
            .hash = "zig_msgpack-0.0.8-evvueB_ZAQBNRm7kdh1FslBxMvpu5WKvU2RrYhUY_Dne",
        },
        .@"path-exporter" = .{
            // path 为本地包的路径
            .path = "../package_management_exporter",
        },
    },
    // 包所包含的源文件，一般用于在对外提供包时才使用，还是建议养成写清楚paths的习惯
    .paths = .{
        "src",
        "build.zig",
        "build.zig.zon",
    },
}

以上字段含義為：

  • name：當前你所開發的包的名字
  • version：包的版本，使用 Semantic Version。
  • fingerprint: 該值為校驗和，它與包的名字有關，使用 zig build 時會告訴你應該填什麼。
  • dependencies：依賴項，內部是一連串的匿名結構體，字段 dep_name 是依賴包的名字， url 是源代碼地址， hash 是對應的 hash（源文件內容的 hash）， path是不使用源碼包而是本地目錄時目錄的路徑。 當使用目錄方法導入包時就不能使用url和hash，反之同理。
  • paths：顯式聲明包含的源文件，包含所有則指定為空。

🅿️ 提示

小技巧：如何直接使用指定分支的源碼？

如果代碼託管平臺提供分支源碼打包直接返回功能，就支持，例如 github 的源碼分支打包返回的 url 格式為：

https://github.com/username/repo-name/archive/branch.tar.gz

其中的 username 就是組織名或者用戶名，repo-name 就是對應的倉庫名，branch 就是分支名。

例如 https://github.com/limine-bootloader/limine-zig/archive/trunk.tar.gz 就是獲取 limine-zig 這個包的主分支源碼打包。

而若是想要離線使用本地包時則是先下載源碼包並直接使用絕對或相對路徑導入，例如在下載完包之後放在項目的 deps 目錄下，那麼使用本地包的格式為：

./deps/trunk.tar.gz

🅿️ 提示

目前 zig 已支持通過 zig fetch 來獲取 hash 並寫入到 .zon 中！

編寫包 ​

🅿️ 提示

zig 支持在一個 build.zig 中對外暴露出多個模塊，也就是說一個包本身可以包含多個模塊，並且 lib 和 executable 兩種是完全可以共存的！

如何將模塊對外暴露呢？

可以使用 build 函數傳入的參數 b: *std.Build，它包含一個方法 addModule，它的原型如下：

zig
pub fn addModule(
  b: *Build,
  name: []const u8,
  options: Module.CreateOptions
) *Module

使用起來也很簡單，例如：

zig
_ = b.addModule("exporter", .{
    .root_source_file = b.path("src/root.zig"),
    .target = target,
    .optimize = optimize,
});

這就是一個最基本的包暴露實現，指定了包名和包的入口源文件地址（b.path 是相對當前項目路徑取 Path），通過 addModule 函數暴露的模塊是完全公開的。

🅿️ 提示

如果需要使用私有的模塊，請使用 std.Build.createModule，使用方式和 addModule 同理。

關於二進制構建結果（例如動態鏈接庫和靜態鏈接庫），任何被執行 install 操作的構建結果均會被暴露出去（即引入該包的項目均可看到該包的構建結果，但需要手動 link）。

引入包 ​

可以使用 build 函數傳入的參數 b: *std.Build，它包含一個方法 dependency，它的原型如下：

zig
fn dependency(b: *Build, name: []const u8, args: anytype) *Dependency

其中 name 是在在 .zon 中的包名字，它返回一個 *std.Build.Dependency，可以使用 artifact 和 module 方法來訪問包的鏈接庫和暴露的 module。

zig
// 通过 dependency 函数获取到依赖
const pe = b.dependency("path-exporter", .{
    .target = target,
    .optimize = optimize,
});
const te = b.dependency("tarball-exporter", .{
    .target = target,
    .optimize = optimize,
});
// 将 module 添加到 exe 的 root module 中
exe.root_module.addImport("path_exporter", pe.module("exporter"));
exe.root_module.addImport("tarball_exporter", te.module("msgpack"));

🅿️ 提示

dependency 包含一個額外的參數 args，這是傳給對應的包構建的參數（類似在命令行構建時使用的 -D 參數，通常是我們使用 b.options 獲取，通過 std.Build.option 實現），當前包的參數並不會向包傳遞，需要手動顯式指定轉發。
