單元測試 ​

在計算機編程中，單元測試（英語：Unit Testing）又稱為模塊測試，是針對程序模塊（軟件設計的最小單位）來進行正確性檢驗的測試工作。程序單元是應用的最小可測試部件。

——維基百科

基本使用 ​

在 zig 中，單元測試的實現非常簡單，只需要使用 test 關鍵字 + 字符串（測試名字，一般填測試的用途）+ 塊即可。

zig
pub fn main() !void {}

const Basic = struct {
    const std = @import("std");

    test "expect addOne adds one to 41" {

        // 标准库提供了不少有用的函数
        // testing 下的函数均是测试使用的
        // expect 会假定其参数为 true，如果不通过则报告错误
        // try 用于当 expect 返回错误时，直接返回，并通知测试运行器测试结果未通过
        try std.testing.expect(addOne(41) == 42);
    }

    test addOne {
        // test 的名字也可以使用标识符，例如我们在这里使用的就是函数名字 addOne
        try std.testing.expect(addOne(41) == 42);
    }

    /// 定义一个函数效果是给传入的参数执行加一操作
    fn addOne(number: i32) i32 {
        return number + 1;
    }
};

const Nestd = struct {
    const std = @import("std");
    const expect = std.testing.expect;

    test {
        std.testing.refAllDecls(S);
        _ = S;
        _ = U;
    }

    const S = struct {
        test "S demo test" {
            try expect(true);
        }

        const SE = enum {
            V,

            // 此处测试由于未被引用，将不会执行.
            test "This Test Won't Run" {
                try expect(false);
            }
        };
    };

    const U = union { // U 被顶层测试块引用了
        s: US, // 并且US在此处被引用，则US容器中的测试块也会被执行测试

        const US = struct {
            test "U.US demo test" {
                // This test is a top-level test declaration for the struct.
                // The struct is nested (declared) inside of a union.
                try expect(true);
            }
        };

        test "U demo test" {
            try expect(true);
        }
    };
};

test "all" {
    _ = Basic;
}

const allDecl = struct {
    const std = @import("std");
    const builtin = @import("builtin");

    pub fn refAllDecls(comptime T: type) void {
        if (!builtin.is_test) return;
        inline for (comptime std.meta.declarations(T)) |decl| {
            _ = &@field(T, decl.name);
        }
    }
};

假設以上這段代碼在文件 testing_introduction.zig 中，則我們可以這樣子來執行檢測：

shell
$ zig test testing_introduction.zig
1/2 test.expect addOne adds one to 41... OK
2/2 decltest.addOne... OK
All 2 tests passed.

我們通過 zig test 這個命令來執行單個文件的 test，它默認會使用標準庫提供的“測試器”，源碼位於 lib/test_runner.zig。

🅿️ 提示

當測試名字是一個標識符時，將會輸出類似 decltest.addOne... 這種信息，開頭將會是 decltest。

事實上，測試塊具有隱式的返回值類型 anyerror!void，並且測試在正常構建時會被忽略。

當測試失敗時，zig 會將錯誤堆棧跟蹤輸出到標準錯誤輸出，並在所有測試運行後將報告失敗數目。

嵌套測試 ​

zig test 執行時會僅執行文件內的頂級測試塊，如果想執行非頂級的測試塊，則可以定義一個名字為空的頂級測試塊，在其內部引用你需要執行測試的容器即可。

zig
pub fn main() !void {}

const Basic = struct {
    const std = @import("std");

    test "expect addOne adds one to 41" {

        // 标准库提供了不少有用的函数
        // testing 下的函数均是测试使用的
        // expect 会假定其参数为 true，如果不通过则报告错误
        // try 用于当 expect 返回错误时，直接返回，并通知测试运行器测试结果未通过
        try std.testing.expect(addOne(41) == 42);
    }

    test addOne {
        // test 的名字也可以使用标识符，例如我们在这里使用的就是函数名字 addOne
        try std.testing.expect(addOne(41) == 42);
    }

    /// 定义一个函数效果是给传入的参数执行加一操作
    fn addOne(number: i32) i32 {
        return number + 1;

const Nestd = struct {
    const std = @import("std");
    const expect = std.testing.expect;

    test {

        _ = S;
        _ = U;

            test "This Test Won't Run" {
                try expect(false);
            }
        };
    };

    const U = union { // U 被顶层测试块引用了
        s: US, // 并且US在此处被引用，则US容器中的测试块也会被执行测试

            test "U.US demo test" {
                // This test is a top-level test declaration for the struct.
                // The struct is nested (declared) inside of a union.
                try expect(true);
            }
        };

        test "U demo test" {
            try expect(true);
        }
    };
};

test "all" {
    _ = Basic;
}

const allDecl = struct {
    const std = @import("std");
    const builtin = @import("builtin");

    pub fn refAllDecls(comptime T: type) void {
        if (!builtin.is_test) return;
        inline for (comptime std.meta.declarations(T)) |decl| {
            _ = &@field(T, decl.name);
        }

注意，嵌套引用測試在全局測試塊中引用另一個容器後，並不會遞歸，也就是說它僅僅會執行容器的頂層測試塊和它引用的容器的頂層測試塊。

🅿️ 提示

zig 的標準庫還為我們提供了一個函數 std.testing.refAllDecls，專門處理上面這種語法（ _=... 這種語法看起來並不好看）。

它所使用的 std.meta.declarations 只能獲取到公共成員（即被 pub 修飾的），非公共成員需要我們手動以 _ = .. 形式引入測試。

跳過測試 ​

跳過測試的一種方法是使用 zig test 命令行參數 --test-filter [text] 將其過濾掉。這使得測試構建僅包含名稱包含提供的過濾器文本的測試。請注意，即使使用 --test-filter [text] 命令行參數，也會運行非命名測試（名字為空的測試塊）。

要以編程方式跳過測試，請使測試返回錯誤 error.SkipZigTest 並且默認測試運行程序將認為該測試被跳過。所有測試運行後，將報告跳過的測試總數。

檢測內存洩漏 ​

在測試中，我們可以使用 std.testing.allocator 這個內存分配器來檢測內存洩漏，默認測試器將報告使用該分配器發現的任何內存洩漏。

檢查測試模式 ​

我們可以通過 @import("builtin").is_test 來查看當前是否運行在測試器下。
