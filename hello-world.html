Hello World ​

與學習其他編程語言一樣，我們也將從經典的 Hello, World! 程序開始，以此向 Zig 的世界打一聲招呼。

首先，使用 zig init 命令初始化一個可執行項目，然後將以下內容覆蓋寫入到 src/main.zig 文件中。

zig
pub fn main() !void {
    std.debug.print("Hello, World!\n", .{});
}

接著運行 zig build run 命令，你就可以在終端看到熟悉的 Hello, World! 了。

很簡單，不是嗎？

代碼解析 ​

上述程序通過內建函數 @import 導入了 Zig 的標準庫 std。 在 Zig 中，所有內建函數都以 @ 符號開頭，並遵循小駝峰命名法（lowerCamelCase）。

🅿️ 提示

@import 函數用於查找並導入相應名稱的模塊或 Zig 源文件（以 .zig 為後綴）。

Zig 默認可導入三個核心模塊：

  • std：標準庫。
  • builtin：與構建目標相關的信息。
  • root：項目的根文件（編譯時指定的入口文件，通常是 src/main.zig）。

程序的入口點是 main 函數。我們在 main 函數中調用了標準庫 debug 包內的 print 函數，輸出了 "Hello, World!"。

print 函數的用法類似於 C 語言的 printf，它接受兩個參數：第一個是格式化字符串，第二個是包含替換值的元組（tuple）。

  • 格式化字符串：使用 {} 作為佔位符。Zig 會自動推斷值的類型。如果無法推斷，則需要顯式指定，例如 {s} 代表字符串，{d} 代表整數。
  • 參數：第二個參數是一個元組，你可以將其理解為一個匿名結構體。

⚠️ 注意

std.debug.print 主要用於調試，不推薦在生產環境中使用。因為它會將信息打印到 stderr，且在某些構建模式下可能會被編譯器優化掉。 這只是一個入門示例，接下來我們將探討更“正確”的打印方式。

下面的內容涉及更底層的概念，你可以暫時跳過，待熟悉 Zig 後再來回顧。

更標準的輸出方式 ​

“打印 Hello, World”看似簡單，但在 Zig 中，它能引導我們思考一些底層設計。

Zig 本身沒有內置的 @print() 函數，輸出功能通常由標準庫的 log 和 io 包提供。std.debug.print 是一個特例，主要用於調試。

讓我們看一個更規範的例子（但請注意，此代碼同樣不建議直接用於生產環境）：

zig
const std = @import("std");

pub fn main() !void {
    try One.main();
    try Two.main();
    try Three.main();
}

const One = struct {
    // #region one
    pub fn main() !void {
        std.debug.print("Hello, World!\n", .{});
    }
    // #endregion one
};

const Two = struct {
    // #region two
    pub fn main() !void {
        var stdout_buffer: [1024]u8 = undefined;
        var stdout_writer = std.fs.File.stdout().writer(&stdout_buffer);
        const stdout = &stdout_writer.interface;

        var stderr_buffer: [1024]u8 = undefined;
        var stderr_writer = std.fs.File.stderr().writer(&stderr_buffer);
        const stderr = &stderr_writer.interface;

        try stdout.print("Hello {s}!\n", .{"out"});
        try stderr.print("Hello {s}!\n", .{"err"});

        try stdout.flush();
        try stderr.flush();
    } // #endregion two
};

const Three = struct {
    // #region three
    pub fn main() !void {
        // 定义两个缓冲区
        var stdout_buffer: [1024]u8 = undefined; 
        var stderr_buffer: [1024]u8 = undefined; 

        // 获取writer句柄//
        var stdout_writer = std.fs.File.stdout().writer(&stdout_buffer);
        const stdout = &stdout_writer.interface;

        // 获取writer句柄//
        var stderr_writer = std.fs.File.stderr().writer(&stderr_buffer);
        const stderr = &stderr_writer.interface;

        // 通过句柄写入buffer//
        try stdout.print("Hello {s}!\n", .{"out"}); 
        try stderr.print("Hello {s}!\n", .{"err"}); 

        try stdout.flush();
        try stderr.flush();

        // 尝试刷新buffer//
        try stdout.flush(); 
        try stderr.flush(); 
    }
    // #endregion three
};

🅿️ 提示

main 函數的返回類型 !void 是一個錯誤聯合類型。它表示該函數要麼成功執行並返回 void（即無返回值），要麼返回一個錯誤。

這段代碼分別向 stdout 和 stderr 輸出了信息。

  • stdout (標準輸出)：用於輸出程序的正常信息。寫入 stdout 的操作可能會失敗。
  • stderr (標準錯誤)：用於輸出錯誤信息。我們通常假定寫入 stderr 的操作不會失敗（由操作系統保證）。

我們通過 std.io 模塊獲取了標準輸出和標準錯誤的 writer，它們提供了 print 方法，可以將格式化的字符串寫入對應的 I/O 流。

考慮性能：使用緩衝區 ​

print 函數的每次調用都可能觸發一次系統調用（System Call），這會帶來內核態與用戶態之間上下文切換的開銷，影響性能。為了解決這個問題，我們可以引入緩衝區（Buffer），將多次輸出的內容攢在一起，然後通過一次寫入操作完成，從而減少系統調用的次數。

實現方式如下：

zig
pub fn main() !void {
    // 定义两个缓冲区
    var stdout_buffer: [1024]u8 = undefined; 
    var stderr_buffer: [1024]u8 = undefined; 

    // 获取writer句柄//
    var stdout_writer = std.fs.File.stdout().writer(&stdout_buffer);
    const stdout = &stdout_writer.interface;

    // 获取writer句柄//
    var stderr_writer = std.fs.File.stderr().writer(&stderr_buffer);
    const stderr = &stderr_writer.interface;

    // 通过句柄写入buffer//
    try stdout.print("Hello {s}!\n", .{"out"}); 
    try stderr.print("Hello {s}!\n", .{"err"}); 

    try stdout.flush();
    try stderr.flush();

    // 尝试刷新buffer//
    try stdout.flush(); 
    try stderr.flush(); 
}

通過 std.io.bufferedWriter，我們為 stdout 和 stderr 的 writer 添加了緩衝功能，從而提高了性能。

更進一步：線程安全 ​

以上代碼在單線程環境下工作良好，但在多線程環境中，多個線程同時調用 print 可能會導致輸出內容交錯混亂。為了保證線程安全，我們需要為 writer 添加鎖。

你可以使用 std.Thread.Mutex 來實現一個線程安全的 writer。我們鼓勵你閱讀標準庫源碼來深入瞭解其工作原理。
