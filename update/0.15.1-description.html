0.15.1 ​

2025/1/20，0.15.1 發佈，自上一個版本來歷時 5 個月，共有 162 位貢獻者參與，進行了 647 次提交！

Zig 官方團隊直接從 0.14.0 跨越到了 0.15.1。在默認選擇 Zig 的 x86 後端後，調試編譯速度提高了 5 倍；正在開發的 aarch64 後端也緊隨其後。同時，隨著 Writergate 事件以及一系列語言變更和標準庫的調整，大量 API 有破壞性更改；這預示著 async/await 即將重生；也是語言穩定化的最後關頭。

編譯器重大改進 ​

x86 後端性能突破 ​

調試模式的編譯速度提高了 5 倍；這是本次更新最顯著的性能改進。x86 後端現在是調試模式的默認選擇，為縮短開發週期提供了強有力的支持。

aarch64 後端開發進展 ​

aarch64 後端的開發也在穩步推進，持續優化 ARM 平臺支持，為多架構開發提供更好的體驗。

增量編譯功能增強 ​

增量編譯功能得到了進一步優化，現在支持：

  • 與文件系統監視結合使用
  • 僅檢查編譯錯誤模式
  • 更快的重建速度

多線程代碼生成 ​

編譯器現已支持多線程代碼生成，能夠充分利用多核 CPU 的性能優勢。

語言特性重大調整 ​

移除 usingnamespace 關鍵字 ​

這是一個破壞性變更，usingnamespace 關鍵字被完全移除。所有使用 usingnamespace 的代碼都需要重寫，建議採用顯式導入方式替代，以提高代碼可讀性和可維護性。

移除異步關鍵字 ​

async 和 await 關鍵字已被移除，當前異步編程模型也隨之取消，為未來新的異步方案做準備。這預示著 Zig 協程 的重生。

增強對非窮盡枚舉的 switch 支持 ​

新增對非窮盡枚舉使用 switch 語句的支持，提高了枚舉處理的靈活性，能夠更好地處理未知枚舉值，增強代碼的健壯性。

擴展布爾向量運算符支持 ​

布爾向量現在支持更多運算符，包括邏輯運算和比較運算。

內聯彙編：類型化的破壞描述符 ​

內聯彙編現在支持類型化的 clobber 列表，提供了更好的類型安全保證。

指針轉換能力增強 ​

@ptrCast 現在允許從單項指針轉換為切片，提供了更大的靈活性。

調整 undefined 運算規則 ​

對 undefined 值的算術運算規則有所調整，任何與 undefined 的運算結果都將返回 undefined。

加強有損轉換檢測 ​

對於可能導致精度損失的整數到浮點數轉換，編譯器會視為錯誤。

標準庫重大變更 ​

Writergate：I/O 接口完全重構 ​

這是本次更新中最重大的破壞性更改，被社區稱為 "Writergate"：

  • std.io.Reader 和 std.io.Writer 接口被完全重新設計
  • 新接口採用非泛型設計
  • 緩衝區位於接口之上
  • 旨在提高性能並減少不必要的拷貝
  • 需要大量代碼重寫

格式化系統調整 ​

格式化系統進行了重要調整：

  • 調用自定義 format 方法需要使用 {f} 格式說明符
  • format 方法簽名簡化，移除了格式字符串和選項參數
  • 格式化打印不再處理 Unicode
  • 新增了更多格式化說明符

ArrayList 非託管化 ​

容器類型的重要變更：

  • std.ArrayList 現在默認採用非託管方式
  • 開發者需要顯式提供分配器
  • 與其他非託管容器保持一致
  • 提供更好的內存管理控制

鏈表去泛型化 ​

鏈表類型進行了重構，去除了泛型化設計。

HTTP 客戶端和服務器 ​

標準庫新增了 HTTP 支持，提供內置的 HTTP 客戶端和服務器功能。

TLS 客戶端 ​

新增內置 TLS 支持，可以建立安全的 TLS 連接。

環形緩衝區 ​

新增了環形緩衝區類型，提供高效的循環緩衝區實現。

移除 BoundedArray ​

BoundedArray 被移除，建議使用 ArrayList 或固定大小數組替代。

構建系統改進 ​

移除隱式根模塊 ​

構建系統移除了對隱式根模塊的支持，現在需要在構建腳本中明確指定模塊；這提高了構建配置的清晰度和準確性。

macOS 文件系統監視 ​

在 macOS 上新增了文件系統監視功能：

  • 能夠在文件更改時自動觸發重建
  • 支持 --watch 和 --debounce 選項
  • 顯著提高開發效率

Web 界面和時間報告 ​

構建系統現在支持 Web 界面和詳細的時間報告功能。

模糊測試器 ​

Zig 0.15.1 集成了一個內置的模糊測試器：

  • 支持進程內模糊測試
  • 提供 Web UI 界面
  • 支持實時代碼覆蓋率顯示
  • 可以快速發現代碼中的潛在問題

工具鏈更新 ​

LLVM 20 ​

升級到 LLVM 20，帶來了：

  • 更好的優化支持
  • 新的目標架構支持
  • 改進的調試信息生成
  • 更好的 C++ 交互性

FreeBSD 和 NetBSD libc 支持 ​

在交叉編譯時新增了對動態鏈接的 FreeBSD 和 NetBSD libc 的支持。

glibc 2.42 ​

升級到 glibc 2.42，並支持靜態鏈接本機 glibc。

MinGW-w64 更新 ​

MinGW-w64 工具鏈得到了更新，進一步改進了對 Windows 的交叉編譯支持。

zig libc 和 zig cc 增強 ​

zig libc 和 zig cc 命令的功能得到了增強：

  • 更好的 GCC 兼容性
  • 支持更多編譯選項
  • 更清晰的錯誤報告

版本跳躍說明 ​

Zig 官方團隊選擇直接從 0.14.0 跳躍到 0.15.1，這一決策反映了：

  • 本次更新包含的重大變更數量之多
  • 對編譯器性能的重要改進
  • 標準庫接口的重大重構
  • 為未來版本奠定更堅實的基礎

升級挑戰與機遇 ​

主要挑戰 ​

  1. Writergate：I/O 接口的完全重構需要重寫大量相關代碼
  2. 移除 usingnamespace：需要調整導入方式
  3. 異步代碼調整：需要移除 async/await 使用
  4. ArrayList 變更：需要調整容器使用方式

主要機遇 ​

  1. 編譯速度提升：5 倍的調試編譯速度改進
  2. 更清晰的代碼：移除隱式行為，提高代碼可讀性
  3. 更好的性能：新的 I/O 接口設計更高效
  4. 開發效率：文件系統監視功能和模糊測試器

社區影響 ​

這次更新對 Zig 社區產生了重要影響：

  • 學習曲線：新用戶需要適應新的接口設計
  • 遷移工作：現有項目需要進行大量調整
  • 性能收益：編譯速度的顯著提升改善開發體驗
  • 生態系統：庫作者需要更新以適配新接口

技術債務清理 ​

本次更新體現了 Zig 團隊對技術債務的積極清理：

  • 移除了有爭議的 usingnamespace 特性
  • 重構了性能不佳的 I/O 接口
  • 統一了容器類型的設計理念
  • 為未來的語言演進奠定堅實基礎

未來展望 ​

0.15.1 為 Zig 的未來發展奠定了重要基礎：

  • 編譯性能：為大型項目開發提供更好支持
  • 接口設計：更一致、更高效的標準庫
  • 開發體驗：更快的編譯和更好的工具支持
  • 語言穩定性：移除不穩定特性，為 1.0 做準備

路線圖 ​

I/O 作為接口 ​

I/O 系統將繼續作為接口進行發展和完善，為未來的異步編程模型做準備。

建議 ​

對於 Zig 開發者：

  1. 謹慎升級：在測試環境中充分驗證
  2. 分步遷移：逐步調整代碼以適配新接口
  3. 充分利用性能優勢：積極採用有關編譯速度的改進
  4. 關注社區動態：參與社區討論，分享遷移經驗和最佳實踐

0.15.1 是 Zig 發展歷程中的一個重要里程碑，雖然帶來了較多的破壞性變更，但為語言的長期發展和性能提升奠定了堅實的基礎。這標誌著語言穩定化的最後階段，為 1.0 版本的正式發佈做好了充分準備。
